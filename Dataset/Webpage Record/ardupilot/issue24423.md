Description  
We are experiencing data loss for the IMUs when the Flight Controller is configured with External GPS/Compass module. When the module is not present, there is no data loss in the IMUs.  
We can replicate (and validate the proposed solution) with the following parameter set.  
    
```bash     
 EK3_IMU_MASK  7    
LOG_REPLAY 1    
```  
1. Enable LOG_DISARMED  
2. Reboot  
3. Generate ~1min log data  
4. Disable LOG_DISARMED  
5. Reboot  
6. Download log and check with graph sum(RISI[0].DADT,1) sum(RISI[1].DADT,2) sum(RISI[2].DADT,3) IMU[0].TimeUS/1E6  
Looking at the log, we observe a time slip in the recorded data.  
Solution  
It appears for this flight controller the I2C DMA is interfering with the IMUs, resulting in data loss.  
Cherry-picking these upstream commits (on top of Copter-4.3.7) addresses the issue seen. https://github.com/ArduPilot/ardupilot/pull/23568/commits  
With these changes, we can see all three IMUs are being read without data loss, and the accumulated time rises at the same gradient as elapsed time.  
Two log files are attached in this zip. They contain:  
1. The issue present, on Copter-4.3.7 stable (log-copter-4.3.7-issue-present.bin)  
2. The issue resolved, Copter-4.3.7 with cherry-picked commit (log-copter-4.3.7-fixed-with-cherrypick-commits)
