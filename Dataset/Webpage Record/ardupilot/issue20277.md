# Basic Information:
### Title: Copter: Auto takeoff gets stuck if alt-above-home is positive and takeoff alt is terrain
### Issue status: Closed
### Author: rmackay9
### Issue open time: Mar 10, 2022
# Report
### Report author: rmackay9
### Report Time: Mar 10, 2022
### Report Content:
As reported by @Hasi123 here Auto mode (and presumably Guided as well) can get stuck on a takeoff command if an alt-above-terrain is used.  To reproduce the issue in SITL do this:  
- Start SITL copter at the regular location  
- create a short mission with a takeoff command followed by a Waypoint command where both have altitude frames of "AGL/Terrain  
- long MAV_CMD_DO_SET_HOME 0 0 0 0 -35.363 149.165 575  <-- to set a home altitude  
- param set AUTO_OPTIONS 3 <-- to allow arming and taking off in Auto  
- auto  
- arm throttle  
You should see the Copter gets stuck and won't proceed to the waypoint command

I would like to add, that it only gets stuck if you start the mission (switch to AUTO) somewhere, where the terrain is lower than at home. So to reproduce:  
- Start SITL in a hilly/mountainous environment  
- Create and upload a mission starting with a takeoff command in AGL/terrain frame and a waypoint (doesn´t matter if its terrain/relative/absolute)  
- Arm & takeoff in loiter/guided and fly downhill (somewhere, where the terrain is lower than at home)  
- switch to AUTO and copter will get stuck after climbing to target altitude
