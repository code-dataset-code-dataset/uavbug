### Report Content:
I've found that the EKF3's core's individual EKF_origin.alt values can be different by large values especially if the origin is set from the GPS inflight.  
The issue can be reproduced in SITL after adding some debug to NavEKF3_core::setOrigin to print the EKF_Origin.alt and then do the following:  
- param set SIM_GPS_DISABLE 1 (to disable GPS)  
- restart the simulation  
- ALT_HOLD  
- arm throttle  
- rc 3 2000 (wait for the vehicle to climb to at least 10m)  
- rc 3 1500  
- param set SIM_GPS_DISABLE 0 (to re-enable GPS)  
Below shows the debug output and we can see the EKF origin altitudes are different by 56m  
The issue comes from this bit of code in NavEKF3_core::setOrigin() which is adjusting the origin's altitude.  For the core that wasn't lucky enough to set the common origin, it receives an EKF origin with an altitude that has already been adjusted to be the ground altitude and then it adjusts it again.  This leads to the difference in the two ekf origin's altitude being roughly the vehicle's altitude above it's startup altitude (e.g. baro altitude) at the time the origin is set.  
    
```bash     
 if (inFlight) {    
    EKF_origin.alt += (int32_t)(100.0f * stateStruct.position.z);    
}    
```  
As a side note PR \\\#17786 and PR \\\#17766 led me to discover this issue.
