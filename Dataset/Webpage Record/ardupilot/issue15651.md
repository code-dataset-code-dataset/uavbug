### Issue status: Closed

# Report
### Report author: rmackay9
### Report Time: Oct 26, 2020
### Report Content:
The GSF emergency yaw reset seems to be triggering a yaw reset if the GPS is disabled.  
This can be re-created in SITL by doing the following:  
- start Copter in SITL  
- enable EKF3  
- arm and takeoff in Loiter  
- param set GPS_TYPE = 0  
After a few seconds, "EKF3 IMU0 emergency yaw reset" will be displayed on the screen.  This seems incorrect because there is no GPS data available for the GSF feature to work from.  It also leads to a position and velocity reset.  The velocity reset leads to the EKF's velocity estimate jumping to zero as shown below.

## Comment4
### Comment author: priseborough
### Comment Time: Oct 28, 2020
### Comment Content:
So what is happening is that the Copter::ekf_position_ok() function is returning false when the EKF has been without GPS  for too long which causes Copter::ekf_over_threshold() to go true which causes ahrs.request_yaw_reset() to be called. The EKF then honors the reset request.  
This doesn't' t show up unless the copter is moved away from its takeoff location because that enables the EKF-GSF yaw estimator to align and unless it is aligned the yaw reset request cannot be honored.  
We shouldn't be asking for a yaw reset if innovation levels are OK and Copter::ekf_position_ok() is false becasue that indicates the loss of nav is due to no GPS, not bad GPS fusion.
