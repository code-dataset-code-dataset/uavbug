Bug report  
Issue details  
When compassmot mode is entered, most mavlink telemetry messages stop  
Version    
github master from today  
Platform    
[  ] All    
[  ] AntennaTracker    
[ x] Copter    
[  ] Plane    
[  ] Rover    
[  ] Submarine  
Airframe type    
octa-quad-cwx  
Hardware type    
Pixwak4 and CUAV-X7  
How to reproduce using the SITL and mavproxy  
    
```bash     
 sim_vehicle.py -N -v ArduCopter -f octa-quad-cwx -A --uartF=sim:fetteconewireesc --console --map    
param set SERIAL5_PROTOCOL 38    
param set SERVO_FTW_MASK 255    
param set SIM_FTOWESC_ENA 1    
reboot    
watch  ESC_TELEMETRY_1_TO_4 ESC_TELEMETRY_5_TO_8 ATTITUDE    
```  
at this point you should see the telemetry messages on the mavlink console  
Now start compassmot, the telemetry messages will stop  
    
```bash     
 compassmot    
```  
Also tested it on real hardware with two GCS connected simultaneously to two different UARTs:  
- connected mavproxy via USB cable to a Pixhawk4  
- and connected QGroundControl via RFD868x to TELEM1 and used the mavlink inspector  
As soon as I issued compassmot on mavproxy, all mavlink communication with QGroundControl ceased except COMPASSMOT_STATUS and HEARTBEAT messages. Those continue to be send.
