# Basic Information:
### Title: Copter: mission should restart if vehicle is armed in Auto mode
### Issue status: Closed
### Author: rmackay9
### Issue open time: Mar 04, 2021
# Report
### Report author: rmackay9
### Report Time: Mar 04, 2021
### Report Content:
PR \\\#15424 added the AUTO_OPTIONS parameter which allows the vehicle to be armed in Auto mode.  The first time this is done the mission runs as expected but if the vehicle is armed (in Auto) a second time the mission will not start unless the user has switched to another mode and then back again to Auto.  
To reproduce the issue in SITL:  
- start SITL copter with default parameters  
- use "wp editor" create a small mission with a takeoff, waypoint and RTL command  
- param set AUTO_OPTIONS 3 (to enable arming in Auto mode and starting them mission without raising the throttle)  
- Auto (to switch to Auto mode)  
- arm throttle (the vehicle should arm and fly the mission, return to home, land and disarm)  
- arm throttle (this time the vehicle will not start the mission)  
The issue is that "mission.start_or_resume()" is only called from within ModeAuto::init() (see code here).  We should probably instead add some code to the top of the run() command to catch when the vehicle has been armed and then start_or_resume the mission.  Issue \\\#11598 also proposes this solution for other reasons.  
Thanks to @peterbarker and @tridge for uncovering this issue.
