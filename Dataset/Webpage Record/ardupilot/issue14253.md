### Title: EKF2/3: GPS glitch can cause emergency yaw reset
### Issue status: Closed
### Author: rmackay9
### Issue open time: May 01, 2020
# Report
### Report author: rmackay9
### Report Time: May 01, 2020
### Report Content:
I've found that during SITL testing of both EKF2 and EKF3 that a GPS glitch can cause an emergency yaw reset to occur which then leads to the vehicle no longer using the compass.  
To recreate the issue do this:  
- set all parameters to defaults (i.e. rm eeprom.bin)  
- start sim_vehicle from the copter directory (cd ArduCopter; ../Tools/autotest/sim_vehicle.py --map --console)  
- arm throttle  
- rc 3 1800 (to climb to 10m)  
- rc 3 1500 (to stop climbing)  
- rc 2 1200 (to start the vehicle flying forward)  
- param set SIM_GPS_GLITCH_Y 0.0001

I will add a check for these sensor failure modes where possible and inhibit the yaw reset request if it is likely that the impending EKF failsafe is caused by something other than bad yaw.

## Comment3

### Comment Content:
    
20m/s/s isn't healthy, but... disabling mag sensors?    
If a yaw reset was necessary due to a bad yaw angle, then it needs to be assumed that the magnetic yaw was unreliable because using a bad magnetometer after a reset eventually results in the yaw rotating back to a bad value with another loss of navigation.  
The underlying issue here is to that we need to inhibit the yaw reset request if there is an error indication in sensors other than the magnetometer.

## Comment6
### Comment author: priseborough
### Comment Time: May 03, 2020
### Comment Content:
The reset in both these cases is being triggered internally within the EKF and not by the external EKF failsafe. I have removed the internal trigger mechanism verified for both EKF2 and EKF3 that:  
A simulated GPS positon jump does not trigger a yaw reset    
A simulated IMU clipping does not trigger a yaw reset    
A simulated flyaway induced by setting COMPASS_AUTODEC = 0 and COMPASS_DEC = -3 reults ina yaw reset and recovery.  
A PR will be submitted shortly.
