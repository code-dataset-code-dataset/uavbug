### Issue status: Closed

# Report
### Report author: AndKe
### Report Time: May 26, 2019
### Report Content:
Bug report  
if AUTO mode is engaged with no mission items, but MIS_TOTAL indicating some,.. it will result in crash.  
- this is perfectly possible is the parameters are restored from a backup.  
To reproduce in SITL (ArduCopter):    
wp list   // observe no items    
param set MIS_TOTAL 40    //set some items, as if restoring params from backup    
rc 3 1500    
poshold    
arm throttle    
takeoff 20    
AUTO  // now observe that you will instantly see "Mission command with ID 0 has no string" , AUTO is never confirmed by console, link goes down..   in reality, strange things happen, then crash.  
Version    
3.6.8 & Current master  
Platform    
[x ] Copter  
- not sure about the others.

### Comment Content:
This is unfortunately fundamentally related to the fact that you should never manipulate MIS_TOTAL parameter. (Indeed it shouldn't be a parameter, but is). We shouldn't crash in that case though. I've seen this confuse GCS's on downloading missions before as well. I haven't investigated the root cause on the vehicle side, but we should be including protection against this, since we've exposed this as a way to shoot yourself in the foot.

Concept 1: ignore param-sets of MISSION_TOTAL (and a select list of other parameters the GCS should not be touching; just pretend they were set)

Concept 3: add a new AP_PARAM_HIDDEN attribute and use it to hide parameters like the FRAME stuff does

Solution suggestions:    
1:  Just ignore any mission item with Command ID=0  , jump ring to next mission item,  parsing up to MISSION_TOTAL  
2: Given that we agree that CID of 0 is invalid, then just refuse to enter AUTO mode, or stop if that is found.  
CID(and other values) set to zero is the normal thing to expect in an empty flash.
