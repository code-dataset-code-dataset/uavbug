### Title: EKF3: terrain height estimate may quietly fail to fuse rangefinder (no timeout)

# Report
### Report author: rmackay9
### Report Time: Jan 19, 2022
### Report Content:
EKF3 estimates the "terrainState" (height of terrain above the EKF origin) using either a downward facing rangefinder or an optical flow sensor (if GPS is also enabled).  The code for the single state EKF that it uses can be seen here in NavEKF3_core::EstimateTerrainOffset.  
One issue noticed during SITL testing is that there is no timeout nor warning to the user if it fails to fuse rangefinder data.  Instead the EKF will quietly continue with the current "terrainState" until the vehicle moves far enough horizontally or climbs/descends quickly enough so that the "auxRngTestRatio" passes (e.g. falls below 1.0).  This will surely reduce optical flow based position hold performance.  
This issue can be reproduced in SITL by doing the following:  
- start SITL copter  
- enable the rangefinder and flow sensor using the SITL instructions or load the copter-optflow.parm file (you may need to attempt to load this a couple of times because of the enable parameters) and restart SITL  
- graph OPTICAL_FLOW.ground_distance DISTANCE_SENSOR.current_distance/100.0  
- param set WPNAV_SPEED 50 (e.g. 50cm/s)  
- param set WPNAV_SPEEEDUP 50 (e.g. 50cm/s)  
- GUIDED  
- arm throttle  
- takeoff 10  
- right-mouse-button-click on the map and set a destination far away from home with an altitude of about 20m  
- param set SIM_SONAR_POS_Z 1 (to simulate the ground suddenly becoming closer to the vehicle).  Note how the OPTICAL_FLOW.ground_distance smoothly moves to consume the 1m jump  
- param set SIM_SONAR_POS_Z 0 (to remove the jump)  
- param set SIM_SONAR_POS_Z 5 (to simulate a 5m jump in terrain).  Note how the OPTICAL_FLOW.ground_distance will not converge until the vehicle has moved a significant distance horizontally 50m?).  The horizontal distance required can be adjusted by changing EK3_TERR_GRAD from the default of 0.1.  
I think we should probably reset the "terrainState" to the rangefinder based estimate if it fails to fuse the rangefinder for 5 seconds or so.  A warning should probably also be issue at the moment of the reset.
