Bug report  
Issue details  
I tested the following on pixhawk1 but I'm pretty sure it affects others boards too.    
In summary, with signing enabled, receiving RC-Input causes a crash!  
The probability of the problem increases:  
1. if you increase the optimization level from Os to O2 or O3  
2. with higher SCHED_LOOP_RATE    
But it occurs with everything at default too  
Steps to reproduces:  
1. Add env OPTIMIZE -O3 to hwdef.data - you can skip this it just increases the probability  
2. build and upload  
3. using mavproxy run signing setup blabla  
4. reboot the board  
5. wait until long failsafe is triggered and RTL is active - not necessary but it increases the probability of getting the problem.  
6. Connect any SBUS RC receiver into RC-IN port. Actually it could already been connected with the transmitter turned-off then turned-on at this point.  
7. FMU WATCHDOG reset would be triggered now over 50% of times. With O3 it can randomly completely freeze and the watchdog is dead :-( - power cycle would be needed.  
It occurs only once per boot, so if you diconnect and reconnect the reciever over the same boot session it doesn't re-occur.    
But if the RC transmitter was not turned on like in AUTO takeoff for example, then turned-on , it would cause in-flight watchdog reset and possibly crash.  
On ArduPlane; the crash occurs after message "APM: RCInput: decoding SBUS" .. Before it says "Throttle failsafe off" ..    
Increasing scheduler loop rate from 50 to 400 increases the chance the crash occurs  
On ArduCopter; it occurs almost on every boot with everything at default other than enable signing.  Maybe because copter has high SCHED_LOOP_RATE by default  
By the way I'm pretty much sure it occurs in other cases too not related to signing, but I couldn't reproduce other cases
