# Report
### Report author: rmackay9
### Report Time: Aug 22, 2020
### Report Content:
If the GPS is enabled (i.e. GPS_TYPE = 1) while the EKF3 is doing relative aiding using wheel encoders (and possibly vision-position-delta) the EKF failsafe will trigger soon after the vehicle beings moving.  The issue does not happen if the vehicle is stopped or the GPS_TYPE = 0.  
This bug is troublesome because it means EKF3 cannot be setup to use primarily the GPS with wheel encoders as backup.  
The issue is in AP_AHRS_NavEKF::active_EKF_type() which includes a specific check for planes and rovers that force it back to DCM if the EKF is configured to use GPS but is not fusing its data (see code here).  
To reproduce the issue in SITL do the following:  
- follow these wiki instructions to enable wheel encoders  
- param set ARMING_CHECK 0 (to disable the pre-arm check complaining about high HDOP)  
- param set GPS_TYPE 1 (to enable GPS)  
- create a small mission and switch the vehicle to Auto mode  
Two bad things happen soon after the vehicle starts moving:  
- the EKF failsafe triggers and the vehicle is switched to Hold mode  
- the reported altitude jumps between 0 and 584  
The estimation issue clears after a few seconds and the vehicle can be switched back to Auto but the problem will occur again.
